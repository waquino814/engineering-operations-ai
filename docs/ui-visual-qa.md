# UI visual QA

A record of the investigation console's visual review on **2026-10-27**: every implemented route, the states captured, the screenshots, and the defects found. Screenshots are in [images/](images/) and were captured from the real application in headless Chrome 156, over the Chrome DevTools protocol, with a script kept outside the repository.

## How the screenshots were made

- **Application:** `node src/cli.ts serve` on `127.0.0.1:8788`, serving the production build (`pnpm ui:build`), against a **scratch data directory** (`EOAI_DATA_DIR`), not the owner's `~/.engineering-operations-ai`. The owner's running application and saved settings were not touched.
- **Data:** `pnpm demo:seed` (the committed excerpt-derived bundle, a synthetic bundle, a tampered one), plus runs made through the UI with the **Fake (simulated) provider** and evaluation runs with the **scripted** and **simulated** providers. Run ids and timestamps in the images are from that session. No Ollama request was made and no hosted AI was involved.
- **Viewports:** desktop 1440 × 900 (full-page where the page is longer) and mobile 390 × 844 at device scale 2.
- **Checked per page:** document title, console errors, failed or 4xx/5xx requests, broken images, horizontal page overflow.

## Defects found and fixed

Each fix has a regression test; `pnpm check` passes with them.

1. **The console rendered blank when served by the application (`pnpm serve`).** The application sends `Content-Security-Policy: default-src 'self'`, which forbids `new Function`. The console imported the result reader, whose Ajv schemas are compiled at module load with `new Function`, so the whole page failed to start with `EvalError`. It went unnoticed because the Vite dev server sends no such policy and jsdom does not enforce one. **Fix:** the policy is unchanged. The result validator moved to [`src/investigation/result-validator.ts`](../src/investigation/result-validator.ts); the console build replaces it with the same schema precompiled by Ajv's standalone generator ([`scripts/standalone-validator.ts`](../scripts/standalone-validator.ts), a small plugin in [`vite.config.ts`](../vite.config.ts)). The console still validates every result against the full schema. The model-output validator, used only by the server, now compiles on first use. Tests: [`test/investigation/result-validator.test.ts`](../test/investigation/result-validator.test.ts) checks the precompiled validator is self-contained and agrees with the runtime one on every fixture and on malformed documents.
2. **Long hashes clipped in the validation table**, hiding the "What to do" column. `.cell-wrap` now wraps unbreakable text.
3. **The Investigations table's last column was cut off** at 1440 px; provider tags now wrap inside table cells.
4. **On narrow screens a short page stretched the navigation strip** to half the viewport (two auto grid rows splitting the spare height). `grid-template-rows: auto 1fr` at the narrow breakpoint.
5. **`/favicon.ico` returned 404** on every page. The console now links an SVG icon from `src/ui/public/` (a `data:` icon would be blocked by the same policy).

Tests for 2 to 5: [`test/ui/static-assets.test.ts`](../test/ui/static-assets.test.ts). These are source-level checks of the CSS and HTML, not a rendered-layout test; the layout itself was verified in the browser.

## Not fixed, by choice

- Every route shares one document title, "Investigation console · Engineering Operations AI". It is accurate, and per-route titles would be a feature change.
- On mobile the navigation strip scrolls horizontally and hides the last items until scrolled.
- The `Suite` label touches its select box on the Evaluations page.
